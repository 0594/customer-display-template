# 客屏对接（模板匹配版）— 云零售收银金额识别 → 串口客显 + 桌面悬浮窗

## 一、项目简介

通过 **PrintWindow 后台截屏** + **数字模板匹配** 识别云零售收银主窗口的金额，经 **ESC/POS 串口指令**发送到数字客显屏，同时在桌面悬浮窗实时显示。

本版本为**纯模板匹配引擎**，不依赖 Tesseract OCR，模板通过 `//go:embed` 嵌入 exe，**单文件即可运行**。

### 核心特性

- **零干扰收银**：PrintWindow 后台截屏，不弹窗口、不抢焦点、不修改收银窗口
- **纯内存识别**：模板嵌入 exe，截图→二值化→连通域分割→模板匹配全在内存完成，无临时文件
- **双模板自适应**：全屏 / 窗口化（半屏）两套模板，按截图高度自动切换
- **启发式规则**：窄字符判"1"、小尺寸判小数点、象限比例区分 0/6、左右比例区分 3/8
- **桌面悬浮窗**：始终置顶显示金额，无边框可拖拽调整大小，右键菜单
- **托盘运行**：系统托盘图标，状态显示、悬浮窗开关、调试模式、打开日志、重新初始化、设置
- **空闲暂停**：无键盘 / 鼠标 / 扫描枪输入时暂停识别，降低资源占用
- **配置存注册表**：原生设置弹窗，保存立即生效

## 二、工作原理

```
云零售收银主窗口（Flutter 窗口，标题含"云零售"）
        ↓
每 800ms（可配置）：
  1. getWindow() — 缓存窗口句柄，IsWindow 验证有效性
  2. PrintWindow(PW_RENDERFULLCONTENT) + CreateDIBSection 截屏
  3. 最小化检测：IsIconic → 显示"待机"
  4. 空闲检测：GetLastInputInfo 超过设定秒数 → 显示"待机"
  5. 窗口尺寸变化检测：全屏/窗口化切换时跳过3帧防抖
        ↓
模板匹配识别：
  1. 裁剪底部按钮行（底部7.5%高度，左侧30%宽度）
  2. 二值化（gray>150→黑字，否则白底，去边框15px/10px/8px）
  3. 8邻域连通域分析分割字符
  4. 过滤噪点（非小数点且高度<10px丢弃）
  5. ¥锚点定位：找到置信度>0.35的"¥"后只取后面字符
  6. 每个字符：
     - 宽<12且高<15 → 小数点
     - 宽高比<0.60 → "1"
     - 否则模板匹配（IoU交并比相似度）
     - 匹配为"0"时：左上/右上象限像素比>1.3 → 改为"6"
     - 匹配为"8"时：中间7行左/右像素比<0.75 → 改为"3"
  7. 正则提取金额，格式化输出
        ↓
  → 串口发送 ESC/POS 指令到客显屏
  → 桌面悬浮窗更新显示
```

## 三、模板匹配技术参数

| 参数 | 值 | 说明 |
|------|-----|------|
| 模板标准尺寸 | 60×60 | 固定高度缩放，保持原始宽度比例 |
| 二值化阈值 | 150 | gray>150 判为白字（黑底白字按钮） |
| 连通域过滤 | 宽≥1, 高≥2, 宽<80, 高<60 | 捕获小数点，过滤大噪点 |
| ¥锚点置信度 | 0.35 | 低于此值不认为是¥ |
| 数字置信度 | 0.40 | 模板匹配最低相似度 |
| 小数点判定 | 宽<12 且 高<15 | 小尺寸连通域 |
| "1"判定 | 宽高比<0.60 | 窄字符 |
| 0/6区分 | 上半部分左/右象限比>1.3 | "6"左上有尾巴 |
| 3/8区分 | 中间7行左/右比<0.75 | "3"左侧开口 |
| 噪点过滤 | 非小数点且高<10px | 丢弃金额后残留噪点 |
| 全屏/半屏切换 | 截图高度>900px为全屏 | 自动选择对应模板集 |

## 五、编译方法

### 环境要求

- Go 1.21+（开发使用 go1.27.0）
- Windows 10/11
- 无其他依赖（模板嵌入exe，不需要Tesseract）

### 编译命令

```bash
# 单文件版（推荐，模板嵌入exe）
go build -ldflags="-H windowsgui -s -w -X main.version=2.0.0-template" -o "客屏对接_模板版.exe" .
```

参数说明：
- `-H windowsgui`：不显示控制台窗口
- `-s -w`：去除调试信息，减小体积
- `-X main.version=xxx`：注入版本号

编译产物约 **3.5MB**，单文件即可运行，不需要 templates 目录。

## 六、配置说明

配置存储在注册表 `HKCU\Software\客屏对接`：

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| port | 字符串 | COM3 | 串口号 |
| baud_rate | 整数 | 2400 | 波特率 |
| check_interval | 整数 | 800 | 识别间隔（毫秒） |
| idle_timeout | 整数 | 30 | 空闲暂停秒数（0=禁用） |
| window_title | 字符串 | 云零售 | 收银窗口标题关键词 |

### 设置界面

托盘右键 → 设置，可修改：
- 串口号（下拉选择可用串口）
- 波特率
- 检查间隔（毫秒）
- 空闲超时（秒）
- 收银窗口标题
- 清屏测试 / 重新初始化按钮

## 八、悬浮窗

- 默认大小 240×70，显示格式 `RM  金额`
- 无边框，可拖拽移动，四边可调整大小
- 始终置顶（WS_EX_TOPMOST）
- 右键菜单：客屏设置 / 恢复窗口 / 关闭窗口
- 窗口大小自动保存到 `overlay_size.txt`
- 金额变化时更新，无变化时保持显示（防抖）
- 最小化/空闲时显示"待机"

## 九、日志

- 位置：`%APPDATA%\客屏对接\app.log`
- 编码：GBK（Windows默认）
- 正常运行：启动信息、串口状态、错误信息
- 调试模式开启后：每次识别输出连通域数量、¥位置、原始识别串、0/6判定、3/8判定

查看日志：托盘右键 → 打开日志，或直接打开文件。

## 十、常见问题

### Q: 识别不到金额？
1. 确认收银窗口标题包含"云零售"（可在设置中修改关键词）
2. 确认收银窗口不是最小化状态
3. 开启调试模式，查看日志中的连通域数量和原始识别串
4. 尝试全屏和窗口化切换，确认两套模板都能匹配

### Q: 数字识别错误？
- 0识别成6（或反之）：检查左上/右上象限比例，调试模式查看日志
- 3识别成8（或反之）：检查中间行左右比例
- 小数点丢失：确认连通域高度过滤阈值（<10px丢弃）
- 大金额显示不全：调整悬浮窗宽度

### Q: 程序运行一段时间后退出？
- 本版本已修复 `too many callback functions` 崩溃（EnumWindows callback全局只创建一次）
- 查看日志最后几行确认退出原因

### Q: 如何更换模板？
1. 用 `template_test` 工具采集新模板（全屏和半屏各一套）
2. 替换 `templates/` 和 `templates_half/` 目录中的PNG
3. 重新编译（模板通过embed嵌入，必须重新编译才生效）

### Q: 支持哪些分辨率？
- 1080p 和 2K 均已测试
- 模板按固定高度缩放，不同分辨率下字符形状一致
- 全屏/半屏自动切换，不需要手动配置

## 十二、技术要点

### 为什么用模板匹配而不是OCR？

1. **识别率更高**：收银界面字体固定，模板匹配准确率接近100%；Tesseract对单个数字常有误识（0.8→0.3等）
2. **速度更快**：纯内存像素比较，单次识别<10ms；Tesseract需要外部进程调用
3. **体积更小**：单文件3.5MB；Tesseract便携版约45MB
4. **无磁盘写入**：识别过程全在内存；Tesseract需要写临时PNG文件
5. **可解释性强**：每个数字的判定有明确规则，调试方便

### 关键修复记录

- **callback泄漏**：EnumWindows每次调用创建NewCallback不释放，约30分钟耗尽2000上限导致崩溃 → 改为全局只创建一次
- **0/6误识**：顶部右侧无像素法在半屏下不生效 → 改为象限比例法（全屏半屏通用）
- **3/8误识**：模板相似度不足以区分 → 添加中间行左右比例启发式
- **全屏/半屏差异**：固定高度缩放+双模板集解决
- **噪点干扰**：金额后残留小连通域导致四舍五入错误 → 高度<10px过滤
